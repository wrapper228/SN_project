# История Telegram-чата

В репозитории приложен экспорт реального диалога с ботом:

- основной файл: `bot_demo.pdf`
- исходный экспорт: `ChatExport_2026-05-13/`
- HTML-файл экспорта: `ChatExport_2026-05-13/messages.html`

## Как смотреть

Самый удобный способ:

1. открыть файл `bot_demo.pdf` прямо из репозитория;
2. при необходимости скачать репозиторий и открыть исходный HTML `ChatExport_2026-05-13/messages.html` локально в браузере.

PDF добавлен специально для удобного просмотра на GitHub. Папка с HTML-экспортом сохранена как исходный материал.

## Что эта история подтверждает

Экспорт показывает, что система действительно работала end-to-end:

- Telegram-бот принимал команды;
- backend создавал задачи;
- локальный Windows-клиент забирал их через polling;
- бот получал промежуточные события и скриншоты;
- interrupt-сообщение пользователя прерывало активную задачу;
- итоговый ответ возвращался обратно в Telegram.

## Что особенно полезно показать преподавателю

### 1. Старт бота

В начале истории видно успешный `/start` и ответ:

`Telegram frontend connected. Send a task and the backend will pass it to the Windows client.`

Это показывает, что Telegram-frontend работает.

### 2. Создание и выполнение задачи

В истории есть task id вида:

`Task accepted: ...`

После этого идут:

- промежуточные текстовые события;
- скриншоты;
- внутренние шаги агента;
- финальный ответ по задаче.

Это подтверждает, что backend и local client реально взаимодействовали.

### 3. Interrupt во время выполнения

В чате есть момент, где пользователь пишет:

`так, прекрати выполнение задачи`

А бот отвечает:

`Interrupt sent to active task.`

После этого агент корректно останавливает текущее выполнение и завершает задачу.

Это хороший демонстрационный момент, потому что он показывает не просто “один запрос — один ответ”, а управление уже запущенной задачей через backend.

### 4. Полный сценарий с анализом документов

Во второй половине экспорта виден более сложный сценарий:

- постановка задачи про чеки;
- промежуточные действия агента;
- использование локального desktop runtime;
- итоговый осмысленный ответ в Telegram.

Это уже демонстрирует практическую полезность системы, а не только базовую транспортную связку.

## Зачем этот экспорт в репозитории

Он нужен как доказательство того, что проект был не только собран по структуре, но и реально использовался в рабочем сценарии:

- frontend существует;
- backend существует;
- local client существует;
- между ними действительно есть связанный рабочий цикл.
